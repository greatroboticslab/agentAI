The cause is in Ultralytics 8.4.37 (the locked scorer's pin; 8.4.129 has the same code), not in D1's detectors and not in the EXIF frame. `ultralytics.data.utils.exif_size` swaps width and height for EXIF orientation 6 or 8 only when PIL names the file's format "JPEG", and PIL names an iPhone photo carrying an MPF segment "MPO". ood23 holds 289 such photos tagged 6 or 8 (257 tagged 6, 32 tagged 8). For the 289 the label cache records the stored landscape size (4032 × 3024), while the loader (cv2, which applies the orientation) returns the portrait frame the labels are in (each source XML: width 3024, height 4032). The validator sorts its rect batches by the cached aspect ratio, so these photos sit in landscape batches (512 × 672, or 576 × 672 in the last), and LetterBox(scaleup=False) shrinks each by a further 0.8 (0.9) that ratio_pad does not record. Ultralytics matches predictions with the ground truth in letterbox space, so its own numbers stay self-consistent, and so does every identity record (identity mode never runs E3's geometry check). E3's inverse geometry maps every box back to that factor times its place: WY_2's one box (class 12, cx 0.545470) comes back at 0.8 × 0.545470 = 0.436376, 0.109094 off. ood22 holds no image tagged 3, 6 or 8 (1,912 untagged, 3 MPO tagged 1), and dev, ImageWeeds, ooddev_v1 and the probe allow only tags none, 0 and 1. It never read the size the label cache holds. Staging transposed copies of the exam's images, as deviation 2 did for D6's training rows, cannot run: the locked scorer refuses any exam image whose sha256 is not LOCK v1's.
